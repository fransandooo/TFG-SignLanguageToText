\chapter{Experiments}
\label{chap:experiments}
\setcounter{section}{0}

This chapter presents the experimental process chronologically, reflecting the project's evolution
from its inception to final validation. The quantitative part is organised as seven phases. Each
phase states what it tries to test, which configuration is used, which results are obtained, what
the result contributes, what it does not solve, and whether the phase objective is achieved. This
structure is intended to make the experimental reasoning understandable without requiring prior
knowledge of the repository or the intermediate notebooks.

The chapter begins with the initial hand-detection and letter-classification pilot studies that
informed the subsequent methodological pivot. The work then progressed into architectural
benchmarking, sequence-length selection, WLASL30 validation, cross-dataset validation on MS-ASL50
and vocabulary scaling. The quantitative block closes with a balance of the evidence and its
limitations.

Every result reported below is backed by stored experiment artefacts, including configurations,
metrics, plots, trained checkpoints and an experiment manifest for each run. The detailed
repository paths needed to reproduce or audit the results are centralised in the reproducibility
guide and internal audit material, so the chapter cites experiment outputs conceptually rather than
repeating long file paths in every caption.

\section{Experimental Methodology}
\label{sec:exp_methodology}

The experimental methodology is organised as a sequence of phases. Each phase has a defined
purpose, configuration, measurement procedure, positive evidence, negative evidence and final
balance. The comparative metrics used throughout the chapter are those defined in
Section~\ref{sec:plan_methods}: Top-1 accuracy, Top-5 accuracy, Macro-F1 and balanced accuracy.

\begin{enumerate}
    \item \textbf{M1 - Exploratory pilots:}
          \begin{itemize}
              \item \textbf{Input:} EgoHands, Kaggle Hand Dataset, Sign Language MNIST and ASL
                    Alphabet.
              \item \textbf{Configuration and measurements:} YOLOv8n, SSDLite-MobileNetV3 and
                    EfficientDet-D0 were compared for hand localisation, while CNN classifiers
                    were trained for static ASL letters. Detection used mAP50, Mean IoU and
                    latency; letter recognition used classification accuracy.
              \item \textbf{Output:} Evidence that detection and static letters were tractable but
                    insufficient for word-level ASL recognition.
          \end{itemize}

    \item \textbf{M2 - Architecture selection:}
          \begin{itemize}
              \item \textbf{Input:} WLASL30 landmark sequences, with 242 train, 56 validation and
                    34 test clips.
              \item \textbf{Configuration and measurements:} Five locally tuned architecture
                    families were compared under the same split, preprocessing and hardware. Each
                    run was evaluated on the fixed test split.
              \item \textbf{Output:} Selection of the best-performing GRU+Attention configuration
                    for downstream experiments.
          \end{itemize}

    \item \textbf{M3 - Sequence-length sweep:}
          \begin{itemize}
              \item \textbf{Input:} WLASL30 landmark sequences and the selected GRU+Attention
                    architecture.
              \item \textbf{Configuration and measurements:} Three maximum sequence lengths were
                    tested, 32, 64 and 96 frames, each with seeds 42, 123 and 2026.
              \item \textbf{Output:} Selection of \texttt{max\_frames}=64 as the default temporal
                    input length.
          \end{itemize}

    \item \textbf{M4 - WLASL30 validation:}
          \begin{itemize}
              \item \textbf{Input:} The WLASL30 fixed split and WLASL100 filtered to the same 30
                    glosses.
              \item \textbf{Configuration and measurements:} The fixed split used three seeds,
                    while the complementary validation used Stratified 5-Fold Cross-Validation with
                    class distribution preserved.
              \item \textbf{Output:} Mean and standard deviation estimates for the selected
                    configuration under seed and split variation.
          \end{itemize}

    \item \textbf{M5 - Cross-dataset validation:}
          \begin{itemize}
              \item \textbf{Input:} MS-ASL50 landmark sequences, with 1{,}410 train, 306 validation
                    and 236 test clips.
              \item \textbf{Configuration and measurements:} The selected configuration was
                    retrained with the same preprocessing and three seeds, changing only the
                    dataset path and vocabulary.
              \item \textbf{Output:} Evidence about whether the pipeline reproduced on a second
                    ASL corpus.
          \end{itemize}

    \item \textbf{M6 - Vocabulary scaling:}
          \begin{itemize}
              \item \textbf{Input:} WLASL subsets from 100 to 1{,}500 classes, plus the 30-class
                    reference.
              \item \textbf{Configuration and measurements:} The selected configuration was
                    retrained with \texttt{max\_frames}=64 and seed 42. Larger subsets used the
                    extended budgets recorded in their manifests.
              \item \textbf{Output:} A scaling curve relating vocabulary size, per-class data
                    availability and test performance.
          \end{itemize}

    \item \textbf{M7 - Quantitative balance and limitations:}
          \begin{itemize}
              \item \textbf{Input:} The results and artefacts produced by phases M1 to M6.
              \item \textbf{Configuration and measurements:} No new model is trained. The phase
                    classifies the limitations observed during the previous experiments and
                    separates supported conclusions from claims that remain outside the evidence.
              \item \textbf{Output:} A final assessment of what the quantitative experiments prove,
                    what they do not prove and which objectives are only partially satisfied.
          \end{itemize}
\end{enumerate}

Unless a phase states otherwise, training and evaluation execute on the local workstation described
in Section~\ref{sec:operational_environment}. The standard optimisation schedule uses AdamW with
learning rate $1 \times 10^{-3}$, weight decay $5 \times 10^{-4}$ and label smoothing of $0.1$ on
the cross-entropy loss. The learning rate follows a CosineAnnealingLR schedule. Early stopping
monitors validation Top-1 with patience 30 epochs, and the maximum standard run length is 150
epochs.

Two reliability protocols are used when the sample size permits it. The \textbf{multi-seed
protocol} repeats the same configuration with seeds 42, 123 and 2026, then reports mean $\pm$
standard deviation. This is required on WLASL30 because the test split contains only 34 samples, so
one error changes Top-1 by approximately 2.94 percentage points. The \textbf{Stratified 5-Fold
Cross-Validation} protocol uses WLASL100 filtered to the same 30 classes, 332 total samples and
five non-overlapping folds with class distribution preserved. It complements the multi-seed
protocol by varying the test split itself rather than only the model initialisation.

Test-Time Augmentation (TTA) was excluded from the evaluation protocol. Earlier exploratory runs on
WLASL30 showed that TTA increased the reported Top-1 without a corresponding gain in true
generalisation. Every number in this chapter therefore reflects a single forward pass per test
sample.

\section{Phase 1 - Exploratory Work and Methodological Pivot}
\label{sec:exp_phase1}

\paragraph{Purpose:} The purpose of the first phase is not to obtain the final recognition result. Its role is to decide
whether the project should remain in a pixel-based hand-detection and letter-classification path,
or pivot towards word-level recognition from hand landmarks. The phase therefore evaluates two
simpler problems first: locating hands in images and recognising static ASL letters.

intentionally separated from the later result tables because these pilots do not use the same

\paragraph{Results:} The hand-localisation experiment produced a YOLOv8n detector with approximately \textbf{98\,\%
mAP@0.5} and \textbf{87\,\% Mean IoU} on the held-out test split. This confirmed that locating
hands was technically feasible. In parallel, the static-letter classifiers also achieved high
accuracy on the simplified alphabet task, but the task itself was too far from the final objective:
recognising a word from a temporal ASL clip.

\paragraph{Positive evidence:} The positive contribution of this phase is that it de-risks the front of the pipeline. It shows
that the project does not fail because hands cannot be detected or because hand-shape information
is impossible to learn. It also provides evidence that a visual pipeline can extract useful signal
from ASL-related images.

\paragraph{Negative evidence:} The limitation is that neither pilot solves word-level sign recognition. Static images cannot
represent signs whose meaning depends on movement, and an RGB sequence model would have to learn to
ignore background, lighting and signer appearance from a very small number of clips per class. The
pilot therefore exposes a representation problem rather than a model-selection problem.

\paragraph{Conclusion:} The phase achieves its objective as an exploratory phase. It does not produce a deployable
recogniser, but it justifies the methodological pivot used in the rest of the chapter: each frame
is represented by 21 three-dimensional MediaPipe landmarks, flattened into 63 features, instead of
by a $224 \times 224$ RGB image. This reduces the input dimensionality by approximately
$2{,}389\times$ and moves the learning problem from appearance-based recognition to geometric
sequence classification.

\paragraph{Results:} Table~\ref{tab:exp_arch_comparison} shows that GRU+Attention is the best candidate in this
controlled comparison: 58.82\,\% Top-1 and 91.18\,\% Top-5. The attention layer improves over the
plain GRU by 20.58 percentage points in Top-1 and over the enriched-feature GRU by 11.76 percentage
points. The Transformer baseline reaches 50.00\,\% Top-1, which is competitive but below the
selected recurrent model on both Top-1 and Top-5.

\paragraph{Positive evidence:} The phase supports the choice of a recurrent model with temporal attention. This is coherent with
the structure of isolated sign clips: only some frames contain the most discriminative hand
configuration or motion phase, and the attention head can weight those frames more heavily than
preparation or recovery frames.

\paragraph{Negative evidence:} The comparison is still a single-split result on only 34 test samples, so one error changes Top-1
by approximately 2.94 percentage points. In addition, the table cannot report Macro-F1 or balanced
accuracy for all non-selected candidates because the stored comparison artefact only contains Top-1
and Top-5 for those rows. The result should therefore be read as architecture selection, not as a
final statistical validation.

\paragraph{Conclusion:} The phase achieves its objective. The selected architecture is a bidirectional GRU with hidden size
256, two layers, dropout $0.4$ and a Temporal Attention head. This configuration becomes the
default for every downstream quantitative experiment.

\paragraph{Results:} The 64-frame configuration gives the highest Top-1 mean and the most stable per-class metrics. Its
Macro-F1 standard deviation is $0.93$ percentage points and its balanced accuracy standard
deviation is $0.76$ percentage points, both much lower than the corresponding values at 32 and 96
frames.

\paragraph{Positive evidence:} The sweep supports 64 frames as a practical default. It preserves enough temporal information to
outperform 32 and 96 frames on Top-1, while reducing seed-to-seed variation in Macro-F1 and
balanced accuracy.

\paragraph{Negative evidence:} The phase does not show that 64 frames is universally optimal. Both alternative settings have
higher mean Top-5 accuracy, and the sweep is performed only on WLASL30. A dedicated sweep on
MS-ASL50, where clips are longer on average, remains outside the executed experiments.

\paragraph{Conclusion:} The phase achieves its objective for this project. The selected value is \texttt{max\_frames}=64,
which is fixed for the downstream WLASL30, MS-ASL50 and vocabulary-scaling experiments.

\paragraph{Results:} The Stratified 5-Fold protocol reaches \textbf{63.85\,\% $\pm$ 4.50\,\%} Top-1 and
\textbf{86.46\,\% $\pm$ 2.04\,\%} Top-5. The fixed-split multi-seed protocol reaches
\textbf{58.82\,\% $\pm$ 2.94\,\%} Top-1 and \textbf{78.43\,\% $\pm$ 4.49\,\%} Top-5. The two
numbers differ by approximately five percentage points because they answer different questions: the
k-fold run varies the test partition, while the fixed-split run keeps the 34-sample test set and
varies only the seed.

\paragraph{Positive evidence:} The phase supports the reproducibility objective. The k-fold result is the strongest WLASL30
estimate because it averages over multiple stratified partitions, and the multi-seed result shows
that the selected pipeline does not collapse under different initialisations.

\paragraph{Negative evidence:} The fixed WLASL30 test split remains small. Classes such as \emph{fine}, \emph{thanksgiving} and
\emph{thin} have one or two supported test samples in the stored per-class metrics, so a single
mistake can make their recall appear as zero. This limits the strength of per-class conclusions on
WLASL30.

\paragraph{Conclusion:} The phase achieves the WLASL30 validation objective, with an important qualification: the headline
63.85\,\% Top-1 result is a cross-validation estimate, while the 58.82\,\% Top-1 result is the
stricter fixed-split multi-seed estimate. Both are reported because they describe complementary
sources of uncertainty.

\paragraph{Conclusion:} The phase achieves its objective. It validates that the selected pipeline can be retrained on a

\paragraph{Positive evidence:} The phase quantifies the scaling bottleneck instead of hiding it. The drop is gradual rather than

\paragraph{Negative evidence:} The phase does not show that the selected model scales to large vocabularies in a practically

improvement in validation performance. Because these rows are single-seed, the exact slope of the
curve should not be treated as a statistically validated law.

\paragraph{Conclusion:} The phase achieves its analytical objective but not a deployment objective. It shows that the main
limitation is data starvation at the class level, not simply the number of labels or a single
software failure. It also sets a clear boundary for the project: the implemented pipeline is
appropriate as a research prototype and small-vocabulary recogniser, but it is not a
large-vocabulary ASL translator.

\section{Phase 7 - Quantitative Balance and Limitations}
\label{sec:exp_limitations}

\paragraph{Purpose:} The purpose of the final quantitative phase is to separate what the preceding experiments
demonstrate from what remains unresolved. No new model is trained here. The phase summarises the
positive evidence, the negative evidence and the practical meaning of the results with respect to
the project objectives.

\paragraph{Configuration:} The input to this phase is the set of artefacts generated by phases M1 to M6: configuration files,
metrics, confusion matrices, per-class reports, manifests and audit notes.

\paragraph{Positive evidence:} The quantitative experiments support four project claims. First, landmark-based input is a viable
representation for isolated ASL word recognition. Second, temporal attention improves the recurrent
baseline on WLASL30 under the executed comparison. Third, the same pipeline can be retrained on
MS-ASL50 without dataset-specific architecture changes. Fourth, vocabulary growth exposes a
data-scarcity bottleneck that can be measured directly.

\paragraph{Negative evidence:} The experiments also constrain what can be claimed. The Transformer baseline was not dominant in
the WLASL30 low-data setting, but this does not prove that Transformers are unsuitable for sign
language recognition in general. The WLASL30 fixed test split is too small for precise per-class
conclusions. The MS-ASL50 reconstruction must be interpreted in light of YouTube attrition.
Finally, the scaling study beyond 30 classes is single-seed, so it establishes a downward trend but
not a fully validated variance estimate.

\paragraph{Detailed limitations:} The MediaPipe detection rate on WLASL is approximately 69\,\% at the frame level. Clips with motion
blur, partially occluded hands or hands moving outside the frame produce silent failures that
interpolation mitigates but does not erase. The same caveat applies less strongly to MS-ASL50,
where the average detection rate is 83.9\,\%.

The WLASL30 test split contains 34 samples, so Top-1 accuracy has a resolution of approximately
2.94 percentage points per misclassification. The 5-Fold CV estimate partially mitigates this by
averaging over five stratified partitions, but the fixed-split confusion matrix should not be read
as a definitive per-class diagnosis.

YouTube attrition on MS-ASL is 34.1\,\% of declared source clips. The MS-ASL50 subset reproducible
from the current YouTube state is therefore not identical to the one that was reproducible when the
dataset was released. Comparisons against the original MS-ASL release \cite{joze2019msasl} must be
contextualised by this difference in available clips.

Only the selected GRU+Attention configuration was evaluated cross-dataset. Running the specific
Transformer baseline from Table~\ref{tab:exp_arch_comparison} on MS-ASL50 would test whether its
lower WLASL30 result reflects the low-data regime or the architecture choice itself. That
experiment is a natural extension, but it was not executed within the scope of this project.

The augmentation pipeline was kept fixed throughout the chapter: rotation, scaling, translation,
Gaussian noise and horizontal flip. Horizontal flip conflates left-handed and right-handed signers,
which is acceptable for a small-vocabulary one-hand pipeline but would need re-examination for
two-hand signs and for downstream studies of signer-handedness bias. Class-weighted loss and
minority-class oversampling were also not applied, despite the per-class disparities documented in
Sections~\ref{sec:exp_wlasl30} and~\ref{sec:exp_msasl}.

\paragraph{Conclusion:} The quantitative block passes the reproducibility objective for the selected pipeline: the model is
selected through a controlled comparison, validated through repeated WLASL30 protocols and
reproduced on MS-ASL50. The scalability objective is only partially achieved: the project measures
the degradation from 30 to 1{,}500 WLASL classes, but it does not solve the large vocabulary
setting. The final conclusion is therefore deliberately bounded: this work delivers a traceable,
reproducible research prototype for isolated word-level ASL recognition from hand landmarks, not a
deployment-ready general ASL translator.

\section{Qualitative Validation}
\label{sec:exp_qualitative}

The quantitative experiments in Part I evaluate recognition accuracy under controlled benchmark
conditions. This section evaluates a different question: whether the SignToText prototype is
understandable, responsive and useful when users interact with the application. The questionnaire
therefore measures usability and perceived value, not the technical accuracy of the model, which
was validated through the benchmark experiments above.

\subsection{Survey Design}
\label{subsec:exp_qual_survey_design}

The qualitative validation used a short Google Form completed after participants tested the
SignToText demo~\cite{signtotextSurvey2026}. The form introduced the application as an ASL
recognition prototype that translates detected signs into text and speech. It then collected three
types of data: previous knowledge of sign language, Likert-scale usability ratings and open-ended
feedback about confusion points or requested changes. The expected completion time was
approximately five minutes.

The remaining survey questions were organised as follows:

\begin{enumerate}[1.]
    \item \textbf{Likert-scale usability block:} This block used a 1 to 5 scale and evaluated five
          dimensions: first impression, understood as whether the participant quickly knew what the app
          did and how to start using it; clarity of the buttons and capture modes; comprehensibility of
          the prediction results; perceived response speed; and perceived utility.

    \item \textbf{Feature-preference question:} This question allowed multiple selections, including
          automatic text-to-speech, Top-K alternatives with confidence percentages, temporal attention
          maps, model selection, continuous phrase mode, countdown before recording, gallery upload and
          processing statistics.

    \item \textbf{Recommendation question:} This question used a 1 to 10 scale and was reduced to
          Net Promoter Score (NPS), computed as the percentage of promoters minus the percentage of
          detractors.
\end{enumerate}

result comprehension, with a mean of 3.7, which indicates that the presentation of the prediction
output still needs refinement.

\subsection{Discussion}
\label{subsec:exp_qual_discussion}

The qualitative results show that users understood the prototype's purpose and perceived it as
useful. The high perceived-speed score also suggests that the end-to-end interaction did not feel
slow during the demo.

The main friction appears in result comprehension. Free-text responses and observed user reactions
showed that the temporal attention map and processing statistics confused several participants when
shown without context. Prediction alternatives and speech output are useful to users, while
diagnostic visualisations should be hidden behind an advanced-details control or accompanied by
short explanatory labels.
