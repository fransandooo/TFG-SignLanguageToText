\chapter{Experiments}
\label{chap:experiments}
\setcounter{section}{0}

This chapter presents the experimental process chronologically, reflecting the project's evolution
from its inception to final validation. It begins with the initial hand-detection and
letter-classification pilot studies that informed the subsequent methodological pivot. The work
then progressed into a rigorous architectural benchmarking phase and an extensive hyperparameter
sweep, which ultimately yielded the best-performing configuration. Finally, the process concluded
with multi-seed, cross-validation and cross-dataset validation to assess statistical stability.
Every result reported below is backed by stored experiment artefacts, including configurations,
metrics, plots, trained checkpoints and an experiment manifest for each run. The detailed
repository paths needed to reproduce or audit the results are centralised in the reproducibility
guide and internal audit material, so the chapter cites experiment outputs conceptually rather than
repeating long file paths in every caption.

\section{Experimental Methodology}
\label{sec:exp_methodology}

The experimental methodology is organised as a sequence of phases. Each phase has a defined input,
configuration, measurement procedure and output, so that later sections can report results without
mixing datasets, hyperparameters and interpretation in the same paragraph. The comparative metrics
used throughout the chapter are those defined in Section~\ref{sec:plan_methods}: Top-1 accuracy,
Top-5 accuracy, Macro-F1 and balanced accuracy.

\paragraph{M1: Exploratory pilots.} \textbf{Input:} EgoHands, Kaggle Hand Dataset, Sign Language
MNIST and ASL Alphabet. \textbf{Configuration and measurements:} YOLOv8n,
SSDLite-MobileNetV3 and EfficientDet-D0 were compared for hand localisation, while CNN classifiers
were trained for static ASL letters. Detection used mAP50, Mean IoU and latency; letter recognition
used classification accuracy. \textbf{Output:} evidence that detection and static letters were
tractable but insufficient for word-level ASL recognition.

\paragraph{M2: Architecture selection.} \textbf{Input:} WLASL30 landmark sequences, with 242 train,
56 validation and 34 test clips. \textbf{Configuration and measurements:} five locally tuned
architecture families were compared under the same split, preprocessing and hardware. Each run was
evaluated on the fixed test split. \textbf{Output:} selection of the best-performing GRU+Attention
configuration for downstream experiments.

\paragraph{M3: Sequence-length sweep.} \textbf{Input:} WLASL30 landmark sequences and the selected
GRU+Attention architecture. \textbf{Configuration and measurements:} three maximum sequence lengths
were tested, 32, 64 and 96 frames, each with seeds 42, 123 and 2026. \textbf{Output:} selection of
\texttt{max\_frames}=64 as the default temporal input length.

\paragraph{M4: WLASL30 validation.} \textbf{Input:} the WLASL30 fixed split and WLASL100 filtered
to the same 30 glosses. \textbf{Configuration and measurements:} the fixed split used three seeds,
while the complementary validation used Stratified 5-Fold Cross-Validation with class distribution
preserved. \textbf{Output:} mean and standard deviation estimates for the selected configuration
under seed and split variation.

\paragraph{M5: Cross-dataset validation.} \textbf{Input:} MS-ASL50 landmark sequences, with 1{,}410
train, 306 validation and 236 test clips. \textbf{Configuration and measurements:} the selected
configuration was retrained with the same preprocessing and three seeds, changing only the dataset
path and vocabulary. \textbf{Output:} evidence about whether the pipeline reproduced on a second ASL
corpus.

\paragraph{M6: Vocabulary scaling.} \textbf{Input:} WLASL subsets from 100 to 1{,}500 classes, plus
the 30-class reference. \textbf{Configuration and measurements:} the selected configuration was
retrained with \texttt{max\_frames}=64 and seed 42. Larger subsets used the extended budgets
recorded in their manifests. \textbf{Output:} a scaling curve relating vocabulary size, per-class
data availability and test performance.

Unless a phase states otherwise, training and evaluation execute on the local workstation described
in Section~\ref{sec:operational_environment}: NVIDIA RTX 3050 Ti Laptop GPU (4\,GB VRAM, CUDA
12.x). The standard optimisation schedule uses AdamW with learning rate $1 \times 10^{-3}$, weight
decay $5 \times 10^{-4}$ and label smoothing of $0.1$ on the cross-entropy loss. The learning rate
follows a CosineAnnealingLR schedule. Early stopping monitors validation Top-1 with patience 30
epochs, and the maximum standard run length is 150 epochs.

Two reliability protocols are used when the sample size permits it. The \textbf{multi-seed
protocol} repeats the same configuration with seeds 42, 123 and 2026, then reports mean $\pm$
standard deviation. This is required on WLASL30 because the test split contains only 34 samples, so
one error changes Top-1 by approximately 2.94 percentage points. The \textbf{Stratified 5-Fold
Cross-Validation} protocol uses WLASL100 filtered to the same 30 classes, 332 total samples and
five non-overlapping folds with class distribution preserved. It complements the multi-seed
protocol by varying the test split itself rather than only the model initialisation.

Test-Time Augmentation (TTA) was excluded from the evaluation protocol. Earlier exploratory runs on
WLASL30 showed that TTA increased the reported Top-1 without a corresponding gain in true
generalisation. Every number in this chapter therefore reflects a single forward pass per test
sample.

\section{Phase 1: Exploratory Work and Methodological Pivot}
\label{sec:exp_phase1}

The first months of the project explored two avenues that were eventually superseded by the
landmark + word approach. They are reported here because the lessons drawn from them are the
technical justification of the pivot, not because they appear as headline numbers in the final
system. This section applies Phase M1 from Section~\ref{sec:exp_methodology}: the input is the set
of hand-detection and letter-recognition datasets, the output is the decision to abandon
pixel-based pilots in favour of landmark-based word recognition.

\paragraph{Hand detection with YOLOv8n.} As introduced in the related-work discussion and dataset description, an initial hand-localisation
experiment trained YOLOv8n \cite{jocher2023yolov8} on the joint EgoHands and Kaggle Hand Dataset
corpus described in Section~\ref{subsec:datasets_hd}. The input was the merged and deduplicated
bounding-box dataset, approximately 5{,}223 annotated images after stratified train/validation/test
splitting. The output was a detector with approximately \textbf{98\,\% mAP@0.5} and \textbf{87\,\%
Mean IoU} on the held-out test split. YOLOv8n was selected after comparison with
SSDLite-MobileNetV3 and EfficientDet-D0 because it provided lower inference latency at comparable
detection accuracy on this corpus.

\paragraph{Letter-level pixel classification.} A parallel track trained CNN classifiers on the union of Sign Language MNIST (DS-03) and ASL
Alphabet (DS-04). Coverage was limited to 24 of the 26 ASL letters because \emph{J} and \emph{Z}
require hand motion and cannot be represented by a single static image. Accuracy on this
static-frame classification task was high, but the task was also far simpler than the eventual
project goal: predicting one of $\sim$24 hand poses per frame is a different problem from
predicting a word from a multi-frame sign.

\paragraph{What the exploration revealed.} The bounding-box detector was not the bottleneck, since it worked reliably. The bottleneck was
\emph{representation}. Pixel-based recognition has three properties that are problematic at the
WLASL scale: (i) it carries appearance signal (skin tone, lighting, background) that is irrelevant
to the linguistic content of a sign and that the model has to learn to discount with limited data;
(ii) the parameter cost of an image-conditioned sequence model grows quickly, which makes
overfitting on a few hundred clips per class very likely; and (iii) the geometry of hand
articulation, which is the actual carrier of meaning, is not made explicit to the model.

The pivot to landmark-based word recognition replaced the visual problem with a geometric one: each
frame is reduced from a $224 \times 224$ RGB tensor to 21 three-dimensional keypoints (63
features), a reduction of approximately $2{,}389\times$ in input dimensionality. The representation
discards background and appearance at the source and exposes the joint geometry directly to a
temporal model. The remainder of this chapter studies the resulting pipeline.

\section{Architecture Selection on WLASL30}
\label{sec:exp_phase2}

This section instantiates Phase M2 from Section~\ref{sec:exp_methodology}. The objective is to
select the architecture family that best converts one-hand MediaPipe landmark sequences into
word-level ASL predictions under a fixed WLASL30 split. The input is WLASL30, the 30 most frequent
WLASL classes, with 242 train, 56 validation and 34 test clips. Each row in
Table~\ref{tab:exp_arch_comparison} is the best local configuration retained for that architecture
family before the final comparison. The comparison then holds constant the dataset, landmark
pipeline, hardware, optimiser, loss, batch size and early-stopping rule defined in
Section~\ref{sec:exp_methodology}. The Transformer baseline is the only exception in optimiser
scale, using $d_{\mathrm{model}} = 256$, $\mathrm{nhead} = 8$, four transformer layers,
$\mathrm{lr} = 5 \times 10^{-4}$, $\mathrm{wd} = 1 \times 10^{-4}$ and dropout $0.3$, as recorded
in its experiment manifest.

The ordering in Table~\ref{tab:exp_arch_comparison} is consistent with a low-data setting. Plain
GRU and plain LSTM architectures receive only 242 training examples spread over 30 classes, which
limits the amount of temporal variation that either recurrent architecture can learn. Adding
hand-engineered enriched features, namely bone vectors and inter-joint angles, gives the model a
9-point absolute Top-1 increase over the plain GRU baseline. That gain disappears once temporal
attention is added, because the attention layer can learn which frames carry the discriminative
signal instead of receiving that information through manually designed geometric features.

The Transformer baseline from this comparison is informative because its parameter budget is
competitive with the GRU+Attention model. It underperforms on Top-1, 50.00 versus 58.82, and more
sharply on Top-5, 73.53 versus 91.18. This result suggests that a recurrent sequential prior is
useful when the training set is small. The experiment does not show that Transformer architectures
are unsuitable for SLR in general, only that this specific Transformer configuration did not match
the selected recurrent architecture on WLASL30.

The best-performing configuration, a bidirectional GRU with hidden size 256, two layers, dropout
$0.4$ and a Temporal Attention head, is therefore selected as the default for every downstream
experiment in the chapter. Its confusion matrix on the WLASL30 test split is shown in
Figure~\ref{fig:exp_cm_wlasl30}.

The matrix exposes two structural failure modes. The first is class imbalance at evaluation time:
several test classes have only one or two samples, so a single error is enough to drop their
per-class recall to zero. The second is genuine visual similarity between specific signs: according
to the stored experiment outputs, the most common confusions on this split are \emph{candy}
$\rightarrow$ \emph{who} and \emph{what} $\rightarrow$ \emph{book}, both at 2 of 3 affected
samples, plus single-sample failures on \emph{fine} $\rightarrow$ \emph{help}, \emph{thanksgiving}
$\rightarrow$ \emph{black}, and \emph{cool} $\rightarrow$ \emph{computer}.

The attention layer performs best because sign language clips contain a small number of \emph{key
frames} where the linguistic content is concentrated, surrounded by neutral preparation and
recovery frames; weighting the GRU outputs by a learned attention distribution focuses capacity
where it matters and tolerates variation in execution speed across signers.

\section{Sequence Length Sweep}
\label{sec:exp_seqlen}

This section applies Phase M3 from Section~\ref{sec:exp_methodology} to the selected GRU+Attention
architecture (Section~\ref{sec:exp_phase2}). The objective is to determine the maximum sequence
length \texttt{max\_frames}, which is the only hyperparameter that changes the temporal input shape
seen by the model. Subsampling too aggressively, as in 32-frame sequences, can discard temporal
dynamics. Oversampling, as in 96-frame sequences, can introduce padding and noise on shorter clips.
A multi-seed sweep distinguishes the effect of sequence length from initialisation variance.

The sweep covers nine runs: 3 seeds (42, 123, 2026) $\times$ 3 sequence lengths (32, 64, 96), with
every other variable held fixed at the values in Section~\ref{sec:exp_methodology}. Aggregated
results from the sweep are reported in Table~\ref{tab:exp_seqlen_sweep}.

The 64-frame configuration produces the most stable training across the three seeds. Macro-F1
standard deviation drops to $0.93$ pp, and Balanced Accuracy standard deviation to $0.76$ pp, both
an order of magnitude tighter than at 32 or 96 frames. The sweep does not select the configuration
that maximises any single mean metric, since 32 frames actually edges out 64 on Top-5 (85.29 vs.\
78.43), but it does select the configuration whose mean is least sensitive to the seed. The
selection criterion is reproducibility, not peak Top-1, and that is the criterion this chapter
applies to every downstream choice.

The 64-frame value is therefore fixed as the default for every downstream experiment in this
chapter, including the cross-dataset MS-ASL50 evaluation in Section~\ref{sec:exp_msasl}. A
dedicated sweep on MS-ASL50, where median clip length is approximately 80 frames, would be a
natural extension and is acknowledged in Section~\ref{sec:exp_limitations}.

\section{WLASL30 Validation}
\label{sec:exp_wlasl30}

This section applies Phase M4 from Section~\ref{sec:exp_methodology}. Two independent validation
protocols characterise the selected configuration on WLASL30. The first is the \textbf{Stratified
5-Fold Cross-Validation} run on WLASL100 filtered to the same 30 classes (332 total samples), which
yields a Top-1 mean of \textbf{63.85\,\% $\pm$ 4.50\,\%} and a Top-5 mean of \textbf{86.46\,\%
$\pm$ 2.04\,\%}. This is the headline result because it averages across both initialisation and
split, and because the standard deviations are computed across non-overlapping test partitions. The
second is the \textbf{multi-seed evaluation} on the fixed WLASL30 split at $\mathit{max\_frames} =

The two protocols disagree by approximately five percentage points on Top-1 (63.85 vs.\ 58.82). The
disagreement is informative rather than contradictory: 5-Fold CV varies the test partition itself,
so the Top-1 average is taken over five non-overlapping test partitions of approximately 66 samples
each ($332 / 5 = 66.4$) and effectively smooths the worst single split; the multi-seed protocol
fixes the 34-sample test split and varies only the model initialisation and batch order. Both
quantities are real; they answer different questions. The headline number reported elsewhere in the
work is the 5-Fold mean because it is the more statistically stable of the two and is directly
comparable to the K-Fold standard in the SLR literature.

The per-class behaviour of the selected configuration on the fixed split is concentrated on a small
number of low-support classes. According to the per-class metric outputs, the worst recall values
among supported classes are \emph{fine} (1 sample, recall $0.00$), \emph{thanksgiving} (1, $0.00$),
\emph{thin} (2, $0.00$), \emph{candy} (3, $0.33$), \emph{what} (3, $0.33$), and \emph{cool} (2,
$0.50$). With one to three test samples per class, even a single misprediction yields a 33--100\,pp
recall drop. This is a property of the test split, not of the model: the per-class metric can be
recovered only by enlarging the evaluation set, which is exactly what the cross-dataset experiment
in Section~\ref{sec:exp_msasl} achieves.

\section{Cross-Dataset Validation: MS-ASL50}
\label{sec:exp_msasl}

This section applies Phase M5 from Section~\ref{sec:exp_methodology}. The pipeline was tuned on
WLASL30. To check whether its behaviour is a property of the method or of the benchmark, the same
code path was retrained on MS-ASL50 with no architectural changes and no dataset-specific
hyperparameter tuning. The only fields that differ between the two configurations are the dataset
path and the gloss vocabulary.

\subsection{Building the MS-ASL50 subset}

MS-ASL ships only annotation JSONs and YouTube URLs; the 25{,}513 declared instances must be
retrieved per-clip, and not all of them are still online. The dataset reconstruction audit records
that \textbf{16{,}816 of 25{,}513 clips were successfully downloaded (65.9\,\%)}, with split-level
coverage of 74.0\,\% / 47.5\,\% / 58.0\,\% (train / val / test). The drop-out is dominated by
YouTube videos that have been removed or made private since the dataset was published.

The subset selection itself is constrained by data deficiency. The disk-level audit reports that
only \textbf{6} of the top-30 classes meet the strict 30 train / 5 val / 5 test threshold;
\textbf{17} meet the 20 / 5 / 5 threshold; and \textbf{57} meet the relaxed 20 / 3 / 3 threshold.
An MS-ASL30 reproduction is therefore not viable from the locally available data. The chosen
alternative is \textbf{MS-ASL50}, defined as the 50 classes with the largest train counts among
those satisfying the 20 / 3 / 3 threshold. After landmark extraction, 31 source clips are dropped
because their mean MediaPipe detection rate falls below the 0.3 floor, leaving \textbf{1{,}410
train / 306 val / 236 test (1{,}952 total)}. The mean detection rate across surviving clips is
\textbf{83.9\,\%}, substantially above the WLASL figure (approximately $69\,\%$), consistent with
MS-ASL clips being longer and shot under more controlled conditions.

The central observation is that the Top-1 standard deviations on the two datasets are nearly
identical (2.94 pp on WLASL30 versus 2.89 pp on MS-ASL50). With 7$\times$ fewer test samples on
WLASL30, this is the strongest statement the experiment supports: \emph{training stability is a
property of the pipeline, not of a specific benchmark}. The pipeline does not need dataset-specific
tuning to produce reproducible results on a second ASL corpus.

The absolute Top-1 figure on MS-ASL50 (70.20) is higher than on WLASL30 (58.82), but this is not
evidence that MS-ASL is intrinsically easier. Three structural factors account for the gap. First,
MS-ASL50 has approximately 6$\times$ more training samples (1{,}410 vs.\ 242), which is the
dominant variable in this data regime. Second, the test set is 7$\times$ larger (236 vs.\ 34), so
each individual misclassification moves Top-1 by approximately 0.42 pp instead of 2.94 pp; a finer
measurement grid yields more representative values, which usually means closer to the true
asymptotic performance. Third, MS-ASL clips are sourced from longer, better-lit YouTube educational
material, which is reflected in the higher MediaPipe detection rate. The experiment therefore
supports the claim that the pipeline reproduces; it does not support a claim about intrinsic
dataset difficulty.

The full 50-class confusion matrix for the seed-2026 MS-ASL50 run is too dense to read at inline
chapter size, so it is provided as a full-page figure in
Appendix~\ref{app:additional_experimental_figures}, Figure~\ref{fig:app_cm_msasl50}. The confusion
pattern, as verified by the stored experiment outputs, is dominated by visually adjacent signs. The
largest absolute confusion is \emph{deaf} $\rightarrow$ \emph{need} (4 of 14 samples, 28.6\,\%),
followed by \emph{pencil} $\rightarrow$ \emph{write} and \emph{fish} $\rightarrow$ \emph{lost}
(each 3 of 5, 60.0\,\%), \emph{nurse} $\rightarrow$ \emph{sit} (3 of 6, 50.0\,\%), and
\emph{mother} $\rightarrow$ \emph{woman} (2 of 4, 50.0\,\%). These are recognisable as one-handed,
location-similar pairs whose discriminative cue is fine-grained finger shape rather than gross
trajectory.

The per-class metrics show three classes with $0.00$ recall (\emph{here}, \emph{man}, \emph{woman},
all with three test samples), and six further classes below $50\,\%$ recall (\emph{need} at $0.25$,
\emph{school} at $0.29$, \emph{nurse} at $0.33$, \emph{lost} at $0.33$, \emph{write} at $0.40$,
\emph{doctor} at $0.43$). At the other end, nineteen classes reach perfect recall on this split,
including six with five or more support samples (\emph{teacher} 9, \emph{no} 7, \emph{tired} 7,
\emph{deaf} 6, \emph{please} 5, \emph{like} 5). The headline Macro-F1 of 68.08 is therefore an
average over a strongly bimodal per-class distribution, which is consistent with the higher
Macro-F1 standard deviation (3.44) compared to Top-1 (2.89): per-class recall is a finer-grained
signal and amplifies seed-to-seed variation in which classes happen to be learned best.

The relationship between vocabulary size and Top-1 accuracy is monotonically decreasing across the
entire range and roughly linear in $\log(\mathrm{num\_classes})$ between 30 and 1{,}000 classes.
The curve does not show an abrupt implementation failure. Instead, it matches the reduction in
per-class data as the vocabulary expands. WLASL2000 has a median of approximately ten samples per
class, which is below the regime where a discriminative neural sequence model can separate
fine-grained gestural categories without external pretraining or stronger augmentation. The
bottleneck is the per-class data budget, not an isolated failure of the architecture.

A weaker secondary observation, restricted to the runs above 700 classes, is that the training
curves of the larger subsets show greater sensitivity to early-stopping triggers; runs at 900,
1{,}200, and 1{,}500 classes saturate the maximum-epoch budget without an unambiguous improvement,
while runs below 700 classes consistently early-stop earlier. This is the practical edge of the
data-starvation regime: not a discrete failure point, but a regime where additional training time
stops paying back.

The data-starvation interpretation is corroborated by the parallel-coordinates view in
Figure~\ref{fig:app_scaling_parallel}, which projects every scaling run onto five normalised axes:
mean videos per class, final train accuracy, validation Top-1, test Top-1 and test Top-5. At 30
classes the line stays high across all axes, with a mean of $11.07$ videos per class, train
accuracy of $99.00\,\%$ and validation Top-1 of $63.85\,\%$. At $1{,}500$ classes, the same
relationship collapses from $74.77\,\%$ train accuracy to $11.67\,\%$ validation Top-1, with only
$4.58$ videos per class. The train-side values remain comparatively high while validation and test
metrics fall, which supports the interpretation that sample scarcity drives the scaling behaviour.

\section{Limitations}
\label{sec:exp_limitations}

These experimental results provide empirical support for several core assumptions, yet they also
challenge several prevailing premises. The supported assumptions are that landmark-based input is a
viable representation for isolated ASL recognition, that temporal attention improves the recurrent
baseline on WLASL30, that the selected pipeline can reproduce on MS-ASL50 without dataset-specific
architecture changes and that vocabulary growth is mainly constrained by per-class data
availability. At the same time, the results challenge the assumption that Transformer architectures
dominate recurrent baselines across all data regimes and the assumption that single-seed reporting
is sufficient for small test sets. The remaining constraints are classified into six categories and
addressed systematically below.

\begin{table}[H]
    \centering
    \scriptsize
    \renewcommand{\arraystretch}{1.2}
    \caption{Limitation categories, ordered from data acquisition constraints to modelling choices. Source: self-created from the experimental audit.}
    \label{tab:exp_limitation_categories}
    \begin{tabular}{@{}p{2.8cm} p{4.6cm} p{4.7cm}@{}}
        \toprule
        \textbf{Category}           & \textbf{Where it appears}                 & \textbf{Effect on interpretation}                                               \\
        \midrule
        Landmark extraction quality & WLASL and MS-ASL landmark preprocessing   & Low MediaPipe detection rates reduce the number of informative frames.          \\
        Evaluation resolution       & WLASL30 fixed test split                  & Small test sets make single errors change Top-1 by several percentage points.   \\
        Dataset reconstruction      & MS-ASL download audit                     & YouTube attrition means the reconstructed subset is time-dependent.             \\
        Seed coverage               & Vocabulary scaling beyond 30 classes      & Single-seed runs show the trend but not the exact seed variance.                \\
        Architecture coverage       & Cross-dataset validation                  & Only the selected GRU+Attention configuration was retrained on MS-ASL50.        \\
        Training policy             & Augmentation and class-imbalance handling & Fixed augmentation and unweighted loss leave minority-class effects unresolved. \\
        \bottomrule
    \end{tabular}
\end{table}

\paragraph{Landmark extraction quality.} The MediaPipe detection rate on WLASL is approximately $69\,\%$ at the frame level. Clips with
motion blur, partially occluded hands or hands moving outside the frame produce silent failures
that the linear-interpolation step mitigates but does not erase. The interpolated frames carry no
new information, so any clip with sustained low detection rate effectively provides fewer
informative frames than its nominal length suggests. The same caveat applies less strongly to
MS-ASL50, where the average detection rate is $83.9\,\%$.

\paragraph{Evaluation resolution.} The WLASL30 test split is small, with 34 samples. Even at three seeds, the standard deviation in
Top-1 is bounded below by $\approx$2.94 pp because that is the resolution of one misclassification.
The $58.82 \pm 2.94$ figure should be read as an interval of expected runs, not as a precise
estimate of true generalisation accuracy. The 5-Fold CV mean of 63.85 partially mitigates this by
averaging over five different test partitions, although the absolute resolution per fold remains
limited.

\paragraph{Dataset reconstruction.} YouTube attrition on MS-ASL is $34.1\,\%$ of source clips. The MS-ASL50 subset reproducible from
the current YouTube state is therefore not identical to the one that was reproducible when the
dataset was released. Any direct numerical comparison with results published against the original
MS-ASL release \cite{joze2019msasl} must account for this difference in available clips.

\paragraph{Seed coverage.} Beyond 30 classes, every reported result is single-seed. Differences between adjacent vocabulary
sizes in Section~\ref{sec:exp_scaling}, for example 23.71 at 500 classes versus 19.57 at 700
classes, may sit within plausible seed-to-seed variation. The downward trend is supported by all
scaling runs, but the exact slope should not be treated as a multi-seed estimate.

\paragraph{Architecture coverage.} Only the selected GRU+Attention configuration was evaluated cross-dataset. A run of the specific
Transformer baseline from Table~\ref{tab:exp_arch_comparison} on MS-ASL50 would test whether its
underperformance in Section~\ref{sec:exp_phase2} reflects the WLASL30 low-data setting or the
architecture choice itself. That experiment is a natural extension, but it was not executed within
the scope of this project.

\paragraph{Training policy.} The augmentation pipeline was kept fixed throughout the chapter: rotation, scaling, translation,
Gaussian noise and horizontal flip. Horizontal flip conflates left-handed and right-handed signers,
which is acceptable for a small-vocabulary one-hand pipeline but would need re-examination for
two-hand signs and for downstream studies of signer-handedness bias. Class-weighted loss and
minority-class oversampling were also not applied, despite the per-class disparities documented in
Sections~\ref{sec:exp_wlasl30} and~\ref{sec:exp_msasl}.

\section{Qualitative Validation}
\label{sec:exp_qualitative}

The quantitative experiments in Part I evaluate recognition accuracy under controlled benchmark
conditions. This section evaluates a different question: whether the SignToText prototype is
understandable, responsive and useful when users interact with the application. The questionnaire
therefore measures usability and perceived value, not the technical accuracy of the model, which
was validated through the benchmark experiments above.

\subsection{Survey Design}
\label{subsec:exp_qual_survey_design}

The qualitative validation used a short Google Form completed after participants tested the
SignToText demo. The form introduced the application as an ASL recognition prototype that
translates detected signs into text and speech. It then collected three types of data: previous
knowledge of sign language, Likert-scale usability ratings and open-ended feedback about confusion
points or requested changes. The expected completion time was approximately five minutes.

The Likert block used a 1--5 scale and evaluated five dimensions: first impression, understood as
whether the participant quickly knew what the app did and how to start using it, clarity of the
buttons and capture modes, comprehensibility of the prediction results, perceived response speed
and perceived utility. The feature-preference question allowed multiple selections, including
automatic text-to-speech, Top-K alternatives with confidence percentages, temporal attention maps,
model selection, continuous phrase mode, countdown before recording, gallery upload and processing
statistics. The recommendation question used a 1--10 scale and was reduced to Net Promoter Score
(NPS), computed as the percentage of promoters minus the percentage of detractors.

\subsection{Results}
\label{subsec:exp_qual_results}

The questionnaire collected responses from $N=15$ participants. Table~\ref{tab:exp_qual_likert}
summarises the Likert dimensions. The strongest dimension is perceived utility, with a mean of 4.5
out of 5, followed by perceived speed at 4.3 and first impression at 4.2. The lowest dimension is
result comprehension, with a mean of 3.7, which indicates that the presentation of the prediction
output still needs refinement.

\subsection{Discussion}
\label{subsec:exp_qual_discussion}

The qualitative results show that users understood the prototype's purpose and perceived it as
useful. The high perceived-speed score also suggests that the end-to-end interaction did not feel
slow during the demo.

The main friction appears in result comprehension. Free-text responses and observed user reactions
showed that the temporal attention map and processing statistics confused several participants when
shown without context. Prediction alternatives and speech output are useful to users, while
diagnostic visualisations should be hidden behind an advanced-details control or accompanied by
short explanatory labels.
